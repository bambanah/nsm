# NSM Planner

Plans a Norwegian Singles Method running week from Plan Settings. See `CONTEXT.md` for the domain language and `docs/` for decisions and the planning model.

## Environment variables

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Postgres connection string |
| `BETTER_AUTH_SECRET` | Random secret for signing sessions, e.g. `openssl rand -base64 32` |
| `BETTER_AUTH_URL` | Public base URL of the app, e.g. `http://localhost:3000` |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | GitHub OAuth app credentials |

## Local development

Requires Node 24 and pnpm.

```sh
docker run -d --name nsm-postgres -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=nsm -p 5434:5432 postgres:18
cp .env.example .env   # then fill in BETTER_AUTH_SECRET and the GitHub credentials
pnpm install
pnpm db:migrate
pnpm dev
```

The app runs on http://localhost:3000. Sign up with email and password, or with GitHub once an OAuth app is configured. There is no password reset: reset a forgotten password by deleting the user's row in the database and signing up again.

Other scripts: `pnpm test`, `pnpm lint`, `pnpm format`, `pnpm typecheck`, `pnpm build`, `pnpm start`. After changing `src/db/schema.ts`, run `pnpm db:generate` and commit the new migration in `drizzle/`. `src/db/auth-schema.ts` is generated by `npx auth@latest generate --config src/auth/auth.server.ts --output src/db/auth-schema.ts --adapter drizzle --dialect postgresql`.

## GitHub OAuth app

Create one OAuth app per environment at GitHub > Settings > Developer settings > OAuth Apps > New OAuth App:

- Homepage URL: the `BETTER_AUTH_URL`, e.g. `http://localhost:3000` for dev or the public URL in production.
- Authorization callback URL: `${BETTER_AUTH_URL}/api/auth/callback/github`.

Copy the client ID and a generated client secret into `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET`.

## Deploying to Coolify

1. Add a PostgreSQL resource and copy its internal connection URL.
2. Add an application from this repository with the Dockerfile build pack, exposing port 3000.
3. Set the environment variables above, with `DATABASE_URL` from step 1 and `BETTER_AUTH_URL` set to the public URL.
4. Set the domain to the public URL and deploy.

The container runs migrations on start (`node migrate.js`) and only starts the server if they succeed.
